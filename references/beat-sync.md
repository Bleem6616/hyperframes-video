# 卡点编排：从音频到镜边界

没有 BGM 的片子，镜长按叙事段落定即可，但**静止段检测（见 rhythm-motion.md）照做**。有 BGM 时按下面走，全过程目标只有一个：**每个镜边界落在拍上，高潮落在"换气 + 重拍"上**。

## 一、拿到音频

前置：`source scripts/hf-env.sh`（下文的 `$HF_FFMPEG`、`$HF_TEMP` 由它提供，音频中间产物一律落数据根的 `temp/`）。

| 来源 | 做法 |
|---|---|
| 用户提供本地文件 | 直接用 |
| 抖音视频里的 BGM | `python scripts/grab_douyin_audio.py <URL或视频ID> --out "$HF_TEMP" --download` |
| 用户录屏 | `"$HF_FFMPEG" -i 录屏.mp4 -vn -c:a libmp3lame -b:a 192k bgm.mp3`（水印不影响音频） |

抖音 web 播放器会把音视频分片请求，音频流特征 `v*-web.douyinvod.com/.../media-audio-und-mp4a/?...`，抓到完整 URL 后用 `Referer: https://www.douyin.com/` 直接下载即可（脚本已封装）。意外收益：往往能抓到**完整曲目**而不是视频里那 70 秒片段。

## 二、实测 BPM 与相位

```bash
"$HF_FFMPEG" -v error -y -i bgm.mp3 -ac 1 -ar 44100 "$HF_TEMP/bgm.wav"
python scripts/bpm_grid.py "$HF_TEMP/bgm.wav" --out beats.json
```

脚本做三件事（纯标准库，无 numpy）：

1. **onset 包络**：一阶差分（≈高通，突出鼓点瞬态）→ 半波整流 → 3 帧平滑。HOP 5 ms / WIN 10 ms。
2. **梳状扫描**：60–180 BPM 以 0.25 步长扫，对每个 BPM 找最佳相位；去半/倍频后给出候选表。
3. **判定比值**：候选 BPM 网格点上的 onset 均值 ÷ 全局均值。**比值越大越可信**，用它在半频/倍频之间定案。

输出：`bpm` / `period`（拍长，秒）/ `phase`（首拍偏移，秒）/ `bar`（4 拍小节长）。**第 n 拍 = phase + n × period**。

> 采样率：解码给 **44100** 最稳。脚本会从 wav 头读实际采样率并据此重算 5 ms / 10 ms 窗口，所以 22050 也能得到同样结论；但**不要用早于 2026-10-14 的旧版脚本**——旧版把 `SR` 写死 44100，喂 22050 的 wav 会把时长读成一半、拍长与相位全部错乱，而 BPM 表面看还是对的（实为倍频）。判据：脚本首行打印的"时长"必须与 `ffprobe` 给的时长一致，不一致就说明踩了这个坑。

同时给出**整曲结构表**（每 4 拍一小节的平均能量）。这张表是用来**选可用段落**的：能量腰斩处就是段落收束线，片子做到那里收最自然；能量最高的小节适合放全片最强的一句。

> 实测参考（Hi Noise《We Never》remix，190.01 s 完整版）：BPM **90.25**、拍长 **0.66482 s**、相位 **0.3025 s** → **第 n 拍 = 0.3025 + n×0.66482**。判定比值 4.33（次优 112.75 为 3.80，领先 13.8%）。
> 结构：drop = **第 26 拍 = 17.588 s**（换气 17.30 → 重拍 17.55，比值 5.51，全曲最强）；**第 128 拍 = 85.400 s** 为 32 小节收束线（小节能量 0.0173 → 0.0092 腰斩，此后进 breakdown）；**第 120 拍 = 80.084 s** 是全曲能量最高的小节。→ 可用的第一个完整大段是 0 → 85.400 s。

## 三、定高潮点（全片时间基准）

高潮 = 音乐的"换气 + 重拍"。找法：

1. 逐毫秒看能量包络，找**峰值骤降**处（换气，接近静音）→ 紧接的**骤升**处就是重拍。
2. 用拍网格复核：算出的重拍时间与网格上某一拍的偏差应 **≤2 帧（30fps 下 0.067 s）**。

实测示例：17.44–17.56 s 峰值掉到 17/128（换气），17.58 s 骤升到 95→107（重拍）；网格第 26 拍 = 17.590 s，**误差 10 ms**，达标。

`bpm_grid.py` 会输出候选 drop 点（能量谷 → 骤升的比值排序）以及最近拍号，便于交叉验证。

## 四、段落分析决定结构

看 `beats.json` 里 **4 拍一小节的平均能量**序列：

- 能量低位 + 元素稀少 → 主歌/引入段
- 能量爬升 → build
- 能量骤升 → drop（高潮段）
- 能量回落 → breakdown（收束）

镜的划分要跟段落走。示例：0–13.3 s 主歌 → 13.34 s 新元素 → 16.26 s build-down → **17.59 s drop** → 85.40 s（第 32 小节）能量回落 → 178 s 渐隐。

## 五、建立镜边界表

**每个镜的起止时间必须是拍网格上的点。** 先算好表再写 HTML：

| 镜 | 起（拍） | 起（秒） | 时长 | 内容 |
|---|---|---|---|---|
| s1 | 0–12 拍 | 0.000 | 8.283 | 开场 |
| s2 | 12–20 | 8.283 | 5.319 | 缘起 |
| s3 | 20–26 | 13.602 | 3.988 | 蓄力 + 画面收暗（对齐音乐渐弱） |
| **s4** | **26 拍** | **17.590** | 9.307 | **高潮：锚词砸出** |
| … | … | … | … | … |
| s10 | 120–132 | 80.083 | 5.319 | 结尾金句 |

要点：
- 镜内各元素的入场 tween 时间点也要踩拍（镜内相对时间 = 拍秒 − 镜起点）。
- 小节线（每 4 拍）适合放"新元素进入"。
- 总时长 = 音频裁切长度，**不要为凑整改节奏**。

## 六、裁音频

```bash
# 裁到与工程 data-duration 完全一致，尾部加 0.6s 淡出
"$HF_FFMPEG" -v error -y -i bgm.mp3 -t 85.402 -af "afade=t=out:st=84.802:d=0.6" -c:a libmp3lame -b:a 192k "$HF_PROJECTS/<slug>/assets/bgm.mp3"
```

宿主的 `data-duration` 与 `<audio data-duration>` 都用裁后长度（示例 85.402）。

## 七、高潮对位写法（误差 ≤2 帧）

```
16.4–16.9  画面整体收暗，所有元素淡出
16.9–17.0  静止约 3 帧（这是唯一允许的"静止"，且必须极短）
17.590     爆发：锚词砸出（约占画宽 1/3）+ 墨痕/光环从中心扩散
17.6       锚词下方浮出一行小字（术语名）
17.6–20    保持，只做极轻微的呼吸感
```

- 锚词 2–4 字，是全片的钉子：开头它是困境，结尾被重新定义。
- 中段揭晓结论时可用一次小一号的爆点，**全片最多两次**。
- 转场不要硬切，用"**同一个元素贯穿前后两画面**"：一个圆收拢成点 → 下一镜从同点炸开；一条线延伸成地平线；推进到细节 → 细节铺满展开成下一场景。
- 淡入淡出/闪白/黑场只作辅助，前后画面不要长时间叠在一起。

## 八、音轨挂载

```html
<audio id="bgm" src="assets/bgm.mp3" data-start="0"
       data-duration="85.402" data-volume="0.9" data-track-index="20"></audio>
```

- **必须有 `id`**，否则渲染无声。
- 不得加 `crossorigin`；不要在代码里 `play()`/seek。
- 音量基线：无口播 0.8–0.9；有口播时 BGM 压到 0.2（相对而言 −18 ~ −22 dB 区间）。
- CLI 渲染时会自动压低守 −1 dBTP，不必手动 `-af`。

## 九、交付前的两点核查

1. **站内"同款"要验拍**：平台音乐库里的同名曲若是另一个 remix 版本，卡点整体错位，必须重新对拍。发布时优先用平台已授权的版本。
2. **峰值**：抓来的音频常已顶满 0 dBFS，二次导出时至少留 −1 dBTP，否则平台压缩会让副歌更糊。
