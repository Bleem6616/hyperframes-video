# 节奏验收与静止段消除

这是本流水线里最容易被忽略、也最影响观感的一环。用户对第一版成片的原话是：

> 「每个转场时间太久了，如从 0:04 秒到 0:10 秒，是完全静止的画面内容，不需要为了凑够 3 分钟时长而拖慢节奏。」

**"画面对不对"能靠抽帧看出来，"节奏顺不顺"只能靠测。** 用像素差把"感觉不对"变成数字。

## 一、检测方法

```bash
source scripts/hf-env.sh
python scripts/motion_audit.py "$HF_OUTPUT/<slug>.mp4" --ffmpeg "$HF_FFMPEG"
```

脚本做的事：

1. 用 FFmpeg 抽成 **320×180 灰度、2 fps** 的 rawvideo（一帧 57,600 字节）。
2. 逐帧算**平均绝对像素差**。
3. 阈值 **0.8**：低于它的相邻帧视为"画面静止"，统计连续静止段。

参数：`--width/--height`（默认 320×180）、`--fps`（默认 2）、`--thresh`（默认 0.8）、`--raw`（跳过 ffmpeg，直接读已有 raw）、`--tmp-dir`（中间 raw 放哪，默认读 `$HF_TEMP`）。

> 中间 raw 体积 = 宽 × 高 × 帧数，长片可达数百 MB。脚本默认优先 `$HF_TEMP`，**不要**依赖系统临时目录：系统上 `TMPDIR` 常被预设为系统盘 Temp，而 Python 的 `tempfile` 优先读 `TMPDIR`，不显式指定就会写到系统盘。

输出：总时长、平均/最小/最大帧差、静止段数量、**最长连续静止**、**静止总时长与占比**、最长的几段（含起始秒）。

## 二、达标线（实测校准）

| 指标 | 达标 | 说明 |
|---|---|---|
| 最长连续静止 | **< 1.0 s** | 30 fps 下 30 帧；超过 1 秒观众就会察觉"卡住了" |
| 静止总占比 | **< 5%** | 允许的量只应来自高潮前那 3 帧的刻意静止 |
| 最小帧差 | **> 0.3** | 保证任意两帧之间画面都在变 |

## 三、实测对照（三轮迭代，同一支片子）

| 版本 | 时长 | 最长连续静止 | 静止占比 | 结论 |
|---|---|---|---|---|
| 第一版 | 180 s | **19.0 s** | **88.1 %** | 典型"为凑时长的 PPT 式静止" |
| 第二版 | 84 s | 3.5 s | 32.7 % | 只砍时长不够 |
| 第三版 | 80 s | **0.5 s** | **3.8 %** | 最小帧差 0.38 → 达标 |

关键结论：**砍时长只解决了一半，另一半必须靠"让画面一直在动"。**

## 四、三个消除手段（按性价比排序）

### 1. 全镜贯穿动效（收益最大）

每个镜都挂两条"从镜首跑到镜尾"的 `ease: "none"` tween：

```js
// 背景光晕大幅缓移 + 呼吸缩放
tl.fromTo("#s1-glow", { x: -110, y: -70, scale: 0.78, opacity: 0.5 },
                      { x: 140, y: 100, scale: 1.34, opacity: 1, duration: 8.0, ease: "none" }, 0.05);
// 整幅持续推近（Ken Burns）
tl.fromTo("#s1-wrap", { scale: 1 }, { scale: 1.09, duration: 8.0, ease: "none" }, 0.05);
```

- **幅度必须够大**：2 % 的推近在缩略图尺度上既测不出也看不见；**8–9 % 才有感知**。
- 光晕位移给 ±100px 量级，不要只挪十几像素。
- 起止时间要"包住"整个镜长（首尾各留 0.05 s），保证任意时刻都有 tween 在跑。

### 2. 阅读等待期配可见运动

字幕/引文/三步卡片这类"观众在读取"的画面，最容易出现静默等待。给它们配一条**匀速的进度线**：

```js
tl.fromTo("#s6-rule", { scaleX: 0 }, { scaleX: 1, duration: 10.6, ease: "none" }, 0.6);
```

线扫完刚好是这镜结束，视觉上等于"读秒"，且不影响阅读。

### 3. 图形动效拉满镜长

元素的动作不要"做完就停"，让它持续到该镜结束：

| 图形 | 持续动效写法 |
|---|---|
| 散点 | 整个镜长持续外扩（`x/y` 线性增长） |
| 指针 | 定住目标后保留极轻微摆动（`rotate` ±2°，`sine.inOut`） |
| 柱状 | 持续微升（`scaleY` 1 → 1.16，`ease: "none"`） |
| 气泡 | 两轮飘散，第二轮幅度减半 |
| 植物茎 | 持续生长（`scaleY` 线性） |
| 划线（划掉清单） | `left:0; right:0` + `scaleX` 0→1，**别写死 px 宽度**——实测 552px 的线在 436px 的卡片里伸出 115px |

### 4. 大面积扫光（细线/小元素镜头的兜底）

验收是在 **320×180 灰度**下算平均像素差，所以**只有大面积的亮度变化才算数**。一条 2px 的金线在延展、一个 46×10 的小方块在落位，缩略图里只有零点几像素高，帧差会低于 0.8 被判"静止"——**即使原片上肉眼看得清清楚楚**。

实测：某镜前 4 秒里只有"金线自左向右延展 + 小格逐个亮起"，被判 **4.0 秒连续静止**；另一镜"照片浮出 + 1px 边框波纹外扩"被判 1.5 秒静止。

兜底做法：给这些镜头加一道**横贯画面的扫光**。

```html
<style>
  .sweep {
    position: absolute; top: 0; bottom: 0;
    width: 420px; left: -420px;
    background: linear-gradient(90deg,
      rgba(201,169,97,0) 0%, rgba(201,169,97,0.28) 50%, rgba(201,169,97,0) 100%);
  }
</style>
<div class="sweep" id="s1-sweep"></div>
```

```js
tl.fromTo("#s1-sweep", { x: 0, opacity: 0 },
                       { x: 1800, opacity: 1, duration: 3.0, ease: "none" }, 0.0);
```

- 起点 `left: -420px`（画面外），终点 x 给到"画面宽 + 420"以上，保证完整扫过。
- 只动 `x` 与 `opacity`，不碰布局属性。
- DOM 里放在**背景光晕之后、内容之前**，就不会盖住文字。
- 420px 宽的扫光在 320×180 上占 105×180 px，扫过时该区像素变化约 12 个灰阶，远高于 0.8 阈值。
- **只补 audit 报出来的那几段**：脚本给的是绝对秒数，减去该镜起点就是镜内局部时间，据此定点加扫光即可，不必全片铺。

### 唯一允许的静止

高潮前那 2–3 帧的"屏息"要保留——它是节奏的一部分。这也是达标线不设为 0 的原因。

## 五、改完必须复测

1. 改 `compositions/*.html`
2. `hf lint <proj>`（期望 0/0）
3. 重渲
4. `python scripts/motion_audit.py "$HF_OUTPUT/<slug>.mp4" --ffmpeg "$HF_FFMPEG"`
5. 数字不达标 → 回到第 1 步，优先加"贯穿动效"

## 六、顺带的 lint 陷阱（改节奏时必踩）

- 前后两条 tween 恰好首尾相接（如 `2.6+1.3=3.9` 与下一条从 `3.9` 开始）时，会因浮点精度被判 `overlapping` → **错开 0.05 s**（改成 `3.95`）。
- 同元素两个不同属性的 `fromTo` 都从"初始态"写起时，后者会覆盖前者 → 给后一条加 `immediateRender: false`。
