# 信息流观感参考（16:9 横屏在抖音竖屏信息流里的实际样子）

来源：2026-10-14 用户实机截图反馈（「忘掉沉没成本」发布后）。这两点是 lint 与常规抽帧抓不到的——lint 全绿、静止段 0%、逐帧单看都"好看"，放进信息流才暴露。

> **性质：倾向性参考，不是硬性规范。**
> 遮挡范围随**机型、系统版本、抖音版本、是否登录/是否首次播放**而变，同一条片子在不同设备上被盖住的像素并不一样，任何"安全线"都只是某一台设备的观测值。
> 所以这里的目标是：**在排版本身合理的前提下，减少关键内容被盖住的概率**——不是给每镜套一条线，更不要为了躲遮挡把版式做拧（右半边空一片、内容全都挤到左边，反而更难看）。**版式观感优先，遮挡规避其次。**

## 现象一：右栏会叠在画面上

抖音信息流里 16:9 横屏片上下加黑边、宽度撑满屏幕，**右侧头像 / 点赞 / 评论操作列直接叠在画面上**。实测截图（一台 iPhone，画面宽 500px）：

- 头像圆：x ≈ 87%–99%，纵向压在画面高度 62%–84% 一带
- 操作列（赞/评/藏/转）沿右缘 x ≈ 89%–98% 向下延伸

「忘掉沉没成本」的 scene 5 四行卡片右端正好排在 x > 85%，"感情 / 已经投入"一行被头像压掉；别的机型上被压的可能就变成旁边几像素。

**做法（参考，非必须）**：

| 区域 | 参考范围 | 建议 |
|---|---|---|
| 右侧 | x > 约 1090px（85%） | 装饰元素（背景纹理、光晕、可被截断的图形延伸）放这里最稳 |
| 右侧 | x 1080px 附近以内 | 整块文字/卡片右缘**尽量**收到这附近；不必精确卡线 |
| 底部 | y > 约 662px（92%） | 进度条会压底缘，关键信息别贴到底 |

右对齐排版时，`right` 用 100–200px 区间通常就够了（惯常 64px 偏小）。**注意**：只有当一列文字或一张卡片的**右端**真的顶到最右侧时才算问题；居中的、偏左的内容不受影响，不必跟着挪。

## 现象二：边缘容易融进黑底

信息流背景是**纯黑 #000**，上下黑边与画面近黑背景（如 `#101418`，亮度约 7%）差别很小，观感上像"画面浮在一片黑里"，边界不清晰。

**做法（任选，可叠加）**：

1. **内描边**（工程模板已默认带上，全局一行，各镜自动生效；不想要直接删掉那行即可）：
   ```css
   #root { box-shadow: inset 0 0 0 2px rgba(255, 255, 255, 0.12); }
   ```
2. **边缘提亮**：背景渐变最外圈别暗于 `#1e2228`（中心可以更深）。
3. **首帧**同时是信息流封面，别用黑场或纯渐变（这条一直有效）。

## 自查（可选）：把大概的遮挡区画在抽帧上

想直观看看有没有内容压到边缘时，可以用 `drawbox` 把风险区涂在抽帧上——**这是自查辅助，不是验收门槛**：

```bash
ffmpeg -v error -y -i out.mp4 -ss <镜中点> -frames:v 1 -vf "\
drawbox=x=iw*0.85:y=0:w=iw*0.15:h=ih:color=red@0.30:t=fill,\
drawbox=x=0:y=ih*0.92:w=iw:h=ih*0.08:color=orange@0.30:t=fill" mask-check.png
```

判读：红/橙区里出现**整块关键信息**（成句文字、卡片主体、数字）时，值得微调；只是稍微贴边或纯装饰越界，可以直接放过——不同设备本来就不一样。

## 与既有规则的关系

- 竖屏 9:16 的遮挡区（顶 15% / 底 20% / 右 15%）属**重新排版**范畴，比横屏严格得多（竖屏下操作列几乎贯穿全高）；横屏只是会叠上右栏，程度轻。
- 版式一节的"四周安全边距 ≥64px"仍是对称通用值，本文件不改变它，只是提示右侧可以稍宽一点。
